🔐 JSON Web Token (JWT): Conceptos Fundamentales

¿Qué es un JWT?

Un JSON Web Token es una forma de enviar información segura entre dos partes (cliente ↔ servidor). Es un token codificado en Base64 que contiene tres partes separadas por puntos:

header.payload.firma

Ejemplo real de Enexia:

eyJhbGciOiJIUzM4NCJ9.eyJzdWIiOiJob2xhQGhvbGEuY29tIiwicm9sZXMiOlsiUEFSVElDSVBBTlRFIl0sImlzcyI6ImVuZXhpYSIsImlhdCI6MTc4ODQ3NzI0OCwiZXhwIjoxNzg4NTYzNjQ4fQ.ueZPyvl6IWkEeSuo3VgBkIGDcOVSN_ISCCRsWeTU-O4APKnpwkoho-RHKbG6f0Ax

1️⃣ Header (Cabecera)

Especifica el tipo de token y el algoritmo de firma:

// Decodificado { "alg": "HS384", "typ": "JWT" }

Significado:

  • alg: Algoritmo HMAC SHA-384
  • typ: Es un JSON Web Token

2️⃣ Payload (Carga)

Contiene la información del usuario (NO está cifrada, solo codificada):

// Decodificado { "sub": "hola@hola.com", "roles": ["PARTICIPANTE"], "iss": "enexia", "iat": 1788477248, "exp": 1788563648 }

Claims (Reclamaciones):

  • sub: Subject (email del usuario)
  • roles: Array de roles del usuario
  • iss: Issuer (quién emitió el token)
  • iat: Issued At (cuándo se emitió - Unix timestamp)
  • exp: Expiration (cuándo vence - Unix timestamp)

3️⃣ Firma (Signature)

Es un HMAC calculado usando header + payload + clave secreta:

// En el servidor (Java) HMACSHA384( base64url(header) + "." + base64url(payload), "clave-secreta-del-servidor" )

¿Por qué la firma?

  • Si alguien altera 1 carácter del payload, la firma no coincide
  • El servidor rechaza el token adulterado
  • La clave secreta está SOLO en el servidor (nunca en el frontend)

🔒 Seguridad: Mitos y Verdades

Pregunta Respuesta
¿Está cifrado? ❌ No. Base64 NO es cifrado.
¿Puedo leer el payload? ✅ Sí, cualquiera lo puede leer.
¿Puedo modificarlo? ❌ No. La firma lo detecta.
¿Viaja en la URL? ❌ En un header HTTP seguro.
Nunca pongas datos sensibles (contraseñas, DNI, tarjetas) en el payload. El JWT es para IDENTIFICAR y AUTORIZAR, no para guardar secretos.

🎯 El Ciclo Completo de un JWT en Enexia

1
Usuario hace login
Envía email y contraseña al servidor
2
Servidor valida credenciales
Verifica email y contraseña contra la BD
3
Servidor genera JWT
Crea header + payload + firma con clave secreta
4
Servidor devuelve el token
El cliente recibe el token en la respuesta del login
5

6

8

Si el token es válido, accede a los datos del usuario

⏳ Promesas en JavaScript: Control Asíncrono

¿Qué es una Promesa?

Una Promesa es un objeto que representa el resultado eventual de una operación asíncrona. Es como decirle a JavaScript:

"Haz esto en el futuro y hazme saber cuando termine, sin bloquear lo demás"

Estados de una Promesa

PENDIENTE ↓ ├─→ RESUELTA ✅ (resolve) └─→ RECHAZADA ❌ (reject)
  • Pendiente: La operación aún no termina
  • Resuelta: La operación fue exitosa
  • Rechazada: La operación falló

Sintaxis Básica

const miPromesa = new Promise((resolve, reject) => { // Código asíncrono aquí if (exito) { resolve(resultado); } else { reject(error); } });

📚 Ejemplos Prácticos

A
Promesa Simple: Esperar 2 segundos
const esperar = new Promise((resolve) => { setTimeout(() => { resolve("¡Listo!"); }, 2000); }); esperar.then(resultado => { console.log(resultado); // "¡Listo!" (después de 2s) });
B
Promesa con Rechazo: Validar número
const validar = new Promise((resolve, reject) => { const num = 5; if (num > 10) { resolve("Número válido"); } else { reject("Número muy pequeño"); } }); validar .then(msg => console.log(msg)) .catch(error => console.log("Error:", error));

🔗 Encadenamiento de Promesas (.then())

1
Problema: Callback Hell
// Código "anidado" difícil de leer obtenerUsuario(id, (error, usuario) => { if (error) console.log(error); obtenerPerfil(usuario.id, (error, perfil) => { if (error) console.log(error); obtenerEventos(perfil.id, (error, eventos) => { // ... y así ad infinitum }); }); });
2
Solución: .then() encadenado
obtenerUsuario(id) .then(usuario => obtenerPerfil(usuario.id)) .then(perfil => obtenerEventos(perfil.id)) .then(eventos => console.log(eventos)) .catch(error => console.log("Error:", error));

Ventajas: Código más legible, fácil de seguir de izquierda a derecha.

🚀 Async/Await: Sintaxis Moderna (RECOMENDADO)

async/await es una forma más limpia de trabajar con promesas. Hace que el código asíncrono se vea como síncrono:

Antes
Con .then()
obtenerDatos() .then(datos => procesarDatos(datos)) .then(resultado => mostrarResultado(resultado)) .catch(error => console.log(error));
Después
Con async/await
async function main() { try { const datos = await obtenerDatos(); const resultado = await procesarDatos(datos); mostrarResultado(resultado); } catch (error) { console.log(error); } } main();
Regla de oro: Cuando veas async, la función retorna una Promesa. Cuando uses await, JavaScript espera a que la Promesa se resuelva.

🌐 Fetch API: Hacer Peticiones HTTP desde JavaScript

¿Qué es Fetch?

fetch() es la forma moderna de hacer peticiones HTTP en JavaScript. Devuelve una Promesa que se resuelve con la respuesta del servidor.

Sintaxis básica:

const respuesta = await fetch(url, opciones); const datos = await respuesta.json();

📍 Ciclo Completo de una Petición

1
Crear la petición
Define la URL y las opciones (método, headers, cuerpo)
2
Enviar al servidor
JavaScript hace la petición de forma asíncrona (no bloquea)
3
Recibir respuesta
Cuando el servidor responde, la Promesa se resuelve
4
Procesar datos
Convierte JSON a objeto JavaScript y lo usa

📚 Ejemplos por Método HTTP

GET: Obtener Datos

async function obtenerEventos() { try { const respuesta = await fetch( 'http://localhost:8080/api/eventos' ); const eventos = await respuesta.json(); console.log(eventos); } catch (error) { console.log('Error:', error); } }

POST: Enviar Datos

async function crearEvento(evento) { try { const respuesta = await fetch( 'http://localhost:8080/api/eventos', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify(evento) } ); const resultado = await respuesta.json(); console.log('Creado:', resultado); } catch (error) { console.log('Error:', error); } }

🔄 Estados de la Respuesta HTTP

Rango Significado Ejemplos
2XX ✅ Éxito 200 OK, 201 Created, 204 No Content
3XX ↪️ Redirección 301 Moved Permanently, 302 Found
4XX ❌ Error del cliente 400 Bad Request, 401 Unauthorized, 404 Not Found
5XX 🔥 Error del servidor 500 Internal Server Error, 503 Service Unavailable
Importante: Fetch NO lanza error para códigos 4XX o 5XX. Siempre debes verificar respuesta.ok o respuesta.status.

Verificar el Status de la Respuesta

❌
Malo: Asumir que siempre es éxito
const respuesta = await fetch(url); const datos = await respuesta.json(); // ¿Y si el servidor respondió 401? Vas a intentar procesar error como éxito
✅
Bien: Verificar respuesta.ok
const respuesta = await fetch(url); if (respuesta.ok) { const datos = await respuesta.json(); console.log('Éxito:', datos); } else { console.log('Error:', respuesta.status); }

🎯 Headers HTTP y Autenticación con Token

¿Qué son los Headers?

Los headers son metadatos que acompañan a cada petición HTTP. Son pares clave-valor que le dicen al servidor información sobre la petición.

📋 Headers Comunes

Header Propósito Ejemplo
Content-Type Tipo de datos que envías application/json
Accept Tipo de datos que quieres recibir application/json
Authorization Token de autenticación Bearer eyJhbGc...
User-Agent Información del navegador Mozilla/5.0...
X-Custom-Header Headers personalizados (comienzan con X-) Depende de la API

🔐 El Header Authorization con JWT

Para enviar un JWT, se usa el header Authorization con el formato:

Authorization: Bearer <token_jwt_completo>
Paso 1
Obtener el token después del login
const respuestaLogin = await fetch( 'http://localhost:8080/api/auth/login', { method: 'POST', headers: { 'Content-Type': 'application/json' }, body: JSON.stringify({ email: 'hola@hola.com', password: 'mi-contraseña' }) } ); const datos = await respuestaLogin.json(); const token = datos.token; // 👈 El token que devuelve el servidor
Paso 2
Guardar el token en sessionStorage
sessionStorage.setItem('enexia_token', token);
Paso 3
Recuperar el token para una petición autenticada
const token = sessionStorage.getItem('enexia_token');
Paso 4
Enviar el token en el header Authorization
const respuesta = await fetch( 'http://localhost:8080/api/auth/me', { method: 'GET', headers: { 'Content-Type': 'application/json', 'Authorization': 'Bearer ' + token // 👈 Aquí va el token } } );

🏗️ Función Helper: Petición Autenticada

Para no repetir el código del header en cada petición, crea una función helper (como la de Enexia):

async function peticionAutenticada(url, opciones = {}) { const token = sessionStorage.getItem('enexia_token'); const headersFinales = { 'Content-Type': 'application/json', // Si hay token, lo agrega; si no, no hace nada ...(token && { 'Authorization': 'Bearer ' + token }) }; const respuesta = await fetch(url, { ...opciones, headers: headersFinales }); return respuesta; } // Uso: const respuesta = await peticionAutenticada( 'http://localhost:8080/api/auth/me', { method: 'GET' } );
El operador spread (...) "desempaqueta" objetos. En este caso, si hay token, agrega "Authorization" a los headers; si no hay, no agrega nada.

🍪 Cookies HttpOnly: Autenticación Segura

¿Por qué las Cookies HttpOnly?

Una cookie HttpOnly es la forma SEGURA de almacenar tokens de autenticación. El navegador la guarda, la envía automáticamente en cada petición, pero JavaScript NO puede leerla.

  • ✅ Protege contra XSS (inyección maliciosa de JavaScript)
  • ✅ Se envía automáticamente (funciona con navegación de páginas)
  • ✅ Protección CSRF con SameSite

📋 Flujo Completo: Backend → Frontend

Backend
1. Generar Cookie HttpOnly (LoginResponse)
ResponseCookie cookie = ResponseCookie .from("auth_token", token) .httpOnly(true) // JavaScript NO puede leer .secure(true) // Solo HTTPS .sameSite("Strict") // Protección CSRF .path("/") .maxAge(86400) // 24 horas .build(); response.addHeader(HttpHeaders.SET_COOKIE, cookie.toString());

La respuesta JSON NO incluye el token — la cookie se envía en un header separado.

Red
2. Headers HTTP (Invisible para el usuario)
Response Headers: Set-Cookie: auth_token=eyJhbGc...; HttpOnly; Secure; SameSite=Strict; Path=/; Max-Age=86400 Cuando el navegador recibe esta respuesta: → Guarda la cookie automáticamente → JavaScript NO puede acceder → Se envía en TODAS las peticiones futuras
Frontend
3. Fetch Automático (Sin hacer nada)
// El navegador AUTOMÁTICAMENTE agrega: fetch('http://localhost:8080/api/eventos', { credentials: 'include' // ← IMPORTANTE: incluye cookies }); // Headers enviados automáticamente: // Cookie: auth_token=eyJhbGc... // ¡También funciona con navegación normal! window.location.href = '/pages/dashboard.html'; // La cookie se envía automáticamente

🔄 Comparación: sessionStorage vs HttpOnly

Aspecto sessionStorage HttpOnly Cookie
Vulnerable a XSS ❌ SÍ ✅ NO
Se envía automáticamente ❌ NO (manual con fetch) ✅ SÍ (automático)
Funciona con window.location ❌ NO ✅ SÍ
JavaScript puede leerlo ✅ SÍ ❌ NO (seguro)
Complejidad Baja Media
HttpOnly es el estándar de seguridad. Todos los sitios modernos (Google, GitHub, etc.) usan cookies HttpOnly para autenticación.

⚠️ Punto Importante: credentials

Cuando usas cookies con CORS (origen diferente), DEBES agregar credentials: 'include':

// ❌ MALO: Cookie NO se envía fetch('http://localhost:8080/api/eventos'); // ✅ BIEN: Cookie se envía fetch('http://localhost:8080/api/eventos', { credentials: 'include' });
